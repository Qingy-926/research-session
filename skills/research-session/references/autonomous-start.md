# 会话中的无人值守启动

## 从一句话开始

用户说“启动无人值守模式”“我离开两小时，范围你推荐”等，触发本流程。先完成准备；不能把这句话或任务包选择直接解释成真实控制器已经启动。普通模式默认不变，不要求用户记住术语或填写技术表。

示例：“启动无人值守模式，预算约 10 元，不设总时限。请按项目推荐任务包，列必做、条件扩展、禁区和 GPU 估时，等我确认一次。”

v4 可准备真实项目的卡，但控制器仅允许显式选择的临时合成项目；真实无人值守执行和无人送审仍关闭。已有项目的批准链按[有界自主](autonomy-bounds.md)办理，新入口不接管、不双启、不扩权。

## 先自查，再给成果选项

1. 由当前项目 README 定位任务、约束、现有进程、批准来源和直接证据；已知路径直接读，不全库盘点。不确定项目或目标、且无法自查时才问。文档中的建议、模型共识、旧回执通过均不代替用户批准。
2. 根据真实瓶颈给 2—3 个有差异的成果包；只有一个可行选项时说明原因，不凑数。每项列“交付成果／固定动作与输入／耗时与额度估算／可写位置／禁区／未完成时留下什么”。推荐一项并给依据与估算不确定性。
3. 用户不懂边界时，AI 拟好边界和默认建议，只让用户选择能理解的成果及重要代价。不要仅回“请明确边界”或逐项追问技术参数。可逆的文件格式、实现细节由 AI 决定；资源、科研协议、外发等重要后果不能代选。
4. 每项分为必做和有条件扩展。扩展写出前置动作、可核的触发证据和固定动作；“还有时间”不是扩展理由。目标可以规划得更远，权限不随时间增加。尚未批准的能力明确标成需要新权限，不混入已授权包。

例如，针对“现有结果尚未核清”，可以提出“核对来源和差异清单”“加上既定方法的关键数字复算”“完成已确认实现缺陷的候选修复及回归”。只有项目确实支持这些动作时才推荐，不能凭模板凭空承诺能做。新实验、正式送审或协议变更若无授权，单列为后续决定。

## 一张启动卡，一次关键确认

在现有项目任务书或其普通附件记录卡，README 仅放入口与当前状态，不维护第二套待办。面向用户的卡保持简短：

| 字段 | 必须说清楚 |
|---|---|
| 目标与成果 | 什么算完成、交付到哪里；证据不足时交什么 |
| 推荐与备选 | 具体成果差异、推荐依据、待用户决定的重要代价 |
| 必做与扩展 | 固定动作、输入/配置版本、依赖及触发证据 |
| 时间 | 默认不设整项墙钟截止；列批准有效期、单动作看门狗和收尾安排 |
| 额度 | 默认约 ¥10 软提醒、调用估算、GPU 数量及预计时长区间、项目硬限制；无 GPU 或外部调用写明，估不出则标未知 |
| 范围与禁区 | 可读原件、可写位置、不能触达的对象；是否新增权限 |
| 停止与恢复 | 完成即结束；先到的上限约束动作；缺证、计量失效或未覆盖取舍停相关依赖；不明在途不重放 |
| 批准绑定 | 卡与原件摘要、选择、来源、有效期和撤回状态；不让 AI 自报批准 |

先核既有批准：只有项目/动作/输入/配置/写出/预算/有效期与当前绑定完全匹配，来源可定位且未撤销、未过期，才沿用。展示摘要，不重复索要同一批准；卡或原件变化后只问受影响的新决定，不以“开始新会话”为由重批一遍。

需要新决定时集中展示当前独立缺项及推荐默认值，通过宿主允许的提问方式取得用户对最终卡和具体选择的确认。没回复就不选择、不认领、不新发请求；已有授权且不依赖该选择的只读工作可以继续。口头“随便做”仍先转换为具体可审阅卡，不能写成无限权限。

确认不能替代科研硬门、真实计量或运行能力预检。准备完成但专用控制器不可用时，明确交付“启动卡已准备，真实无人值守尚未启动”；不要承诺关闭会话后仍可持续、后台运行、定时唤醒或真实路线已通。

## 预算怎样推荐

- 根据现有日志、任务规模或小型已授权测量估算动作成本，标明依据与不确定性；不要反推“有八小时就安排八小时新实验”。没有依据时列估算缺口，不猜价格、完成率或 GPU 用量。
- 必做、扩展、主执行、委派和复核共享同一任务费用口径；失败也计。用可见费用回执优先，否则按可见输入（含缓存分类）/输出 token 与用户费率估算；两者都没有就记未知，不把动作预估当实扣。夹具台账仅统计已显式录入的回执，不自动取得会话或代理用量。
- 接近软线（夹具为 80%）或下一付费动作预计越线时，收尾并交接，不中断当前命令，不再派发新的付费动作。可继续独立且已授权的免费步骤。未知付费额度也停止后续新付费；不承诺硬封顶。
- 看门狗优先采用同类实测上界；无实测时采用有依据的保守上界并留约三倍余量，仍不得超过项目单动作硬限制。超时只停止控制器自己的子进程，保留不确定状态，不自动重放。GPU 时长同时列资源数量、依据和不确定性；没有依据就标未知，不擅自测量或启动。
- 完成就结束，不为用完时间或额度增加任务；额外实验、重跑和科研协议更改不继承现有批准。

## 本地启动卡检查

模型把已整理内容写成 JSON 后，从本会话实际加载的技能根执行：

```powershell
python -B "$RS_SKILL_ROOT/scripts/autonomy_start.py" --card "<启动卡.json>"
python -B "$RS_SKILL_ROOT/scripts/autonomy_start.py" --card "<启动卡.json>" --choice "<选项ID>"
python -B "$RS_SKILL_ROOT/scripts/autonomy_start.py" --card "<启动卡.json>" --choice "<选项ID>" --confirmation "<选择记录.json>"
```

`RS_SKILL_ROOT` 的解析仍按[实际加载入口](plugin-invocation.md#independent-review-entry-and-read-only-continuity-check)。检查器只读取卡及获准列入的项目材料计算 SHA，不隐式探测通道配置、台账、数据库或服务，也不写入它们、不执行动作；不得将敏感材料或未经授权的正式台账列入卡。它不是自然语言解析器，也不是文件系统隔离或人类授权认证器。结构化文件由 AI 从当前上下文与人类选择整理，不能要求用户手写。

新卡使用 `research-session/start-card/v2`。保留 v1 只读兼容；下面前一节是历史 v1 字段，新卡差异见末尾。

### v1 只读兼容

- `project_root`、`goal`、`expires_at_utc`；有效期为 UTC 绝对时刻。面向用户按本地时区显示；检查不固定或改变将来执行的时钟。
- `context:[{path,sha256}]`：本项目内的绝对路径与当前字节 SHA，至少绑定 README；必要的输入、配置、批准来源及代码也纳入。外部依赖在卡中显式标明缺口，不能假装已经核验。
- `budgets:{runtime_seconds,closeout_seconds,max_action_seconds,model_calls,gpu_seconds,disk_bytes,cost_minor,currency,cost_metered}`：数字为非负整数，总时长/收尾/单动作时限须正且收尾小于总时长。`currency` 明确三字母币种，`cost_minor` 为其最小货币单位；字段不检查汇率或认证计量器。付费估算非零但无计量声明则阻断该选项。
- `prohibited`、`stop_conditions` 为非空文本列表；`recommended_option` 是候选 ID。
- `options` 为 1—3 项，含 `id,deliverables,reason,write_scope,new_permissions,actions`。新增权限只是显示提醒，不能由列表或检查结果授予。
- 每项动作含 `id,kind,description,context_paths,phase,requires,condition,estimate`；`description` 写具体操作与验收，`context_paths` 指向已绑定的任务书、输入、代码/配置或批准来源，不把笼统 ID 当作固定动作。`kind` 限 `inspect,recompute,candidate_patch,test,draft,approved_task`，仅作描述，不含命令。`phase` 是 `required` 或 `extension`；依赖只能指向同包前面的动作，扩展必须有前置与非空证据条件。必做不能依赖扩展。
- `estimate` 含 `seconds,model_calls,gpu_seconds,disk_bytes,cost_minor`；未知用 `null`，显示缺口并阻断选项，不填零蒙混。动作金额和预算必须用同一注明币种。

选择记录 schema 为 `research-session/start-selection/v1`，其余字段为 `card_sha256,option_id,expires_at_utc,revoked`。摘要绑定卡原始字节；格式、输入、预算或选择变化都不能继承旧绑定。记录可被伪造，必须由宿主另外核人类来源及有效状态，不能仅凭 JSON、SHA 或“我已批准”的自述授予权限。

没有选择输出 `awaiting_choice`；已选择但无匹配记录输出 `awaiting_confirmation`，均 exit 2。匹配记录且本地校验通过输出 `preparation_complete`、exit 0；仅表示准备材料一致。`authorization_verified`、`execution_enabled`、`gate_passed` 始终为 false。成本计量与权限列表也只是声明，未通过该脚本认证。

坏卡、过期、原件漂移、坏依赖或预算不足返回缺口，不猜默认值；只停止依赖该缺口的准备或执行分支。整个脚本不写文件、不延长截止、不刷新批准、不发正式复核。

### v2 夹具运行与交接

- 示例成果包：必做 `核对合成原件`；若核对有输出、由前置动作证明，则扩展 `复算整数清单并写候选`。只读绑定输入，可写指定候选目录；不改原件、不联网；费用 ¥0，GPU 不涉及。真实项目则按实际证据生成成果备选。
- v2 写 `run_id`、`revision`、`previous_card_sha256`；选择记录改用 `research-session/start-selection/v2`，仍绑定精确卡字节。`budgets` 使用 `cost_soft_limit_cny_fen`、`max_action_seconds`、`gpu_seconds`、`disk_bytes` 和 `currency`；无 `runtime_seconds`。动作列 `outputs`、`watchdog_seconds`、`paid`、结构化时间/GPU估算、固定 `operation`，续轮和触发条件也须在卡内。完整合成样例见 `tests/test_autonomy_v2.py`。
- 仅临时合成项目：`python -B scripts/autonomy_run.py start --fixture --card <卡> --choice <ID> --confirmation <选择记录>`。返回 `state_path`；固定动作走 `execute --state <库> --action <ID>`，公开 CLI 不发模型请求。`claim/complete` 只记宿主协作的合成结果，不产生 OS 权限。
- 三轮复核只在测试进程中通过注入离线替身演练，不可从公开 CLI 运行三轮。合成回执、尝试和发送锁与普通台账分离；`fixture_gate_passed` 只供演练，正式 `gate_passed` 始终为假。
- 交接记录从 `status --state <库>` 取得：已完成及原件 SHA、失败/不确定项、费用与未知量、受阻和可继续动作。`pause --state <库> --reason <原因>` 在途时落盘，当前动作收尾后不再派发；`resume --state <库> --card <原卡或已确认修订> --choice <ID> --confirmation <记录>` 不重置轮次、不补发未知在途任务。真实项目准备时仅把现状和下一步写回既有交接，不假装上述命令已启动，不自动创建或唤醒后续会话。
- 真实生产还缺可信宿主批准、完整计量与资源隔离。当前支持固定本地夹具动作的输出上限和子进程看门狗，不是全目录磁盘配额；协作动作、测试记录和夹具台账不得视为受 OS 隔离。真实 GPU、付费委派、正式送审和真实研究项目试点均不启用。
