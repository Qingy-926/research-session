# 有界自主推进（autopilot 纪律）

用户以自然语言请求启动、需要推荐预算或不懂边界时，先走[会话启动](autonomous-start.md)拟任务包和启动卡。v4 无人值守控制器只用于离线夹具；真实项目只准备。既有已批准自动链仍按本文执行，不借新入口扩权或双启。

## 定位

不采用"双模型全自动互审推进"（ARIS 式全自主）：它与判据先行纪律冲突（自主倾向"先跑再说"），
且两个模型互审存在**共同盲区**——独立性必须靠自包含复核包与不同失效模式，不是靠模型数量。

本工作流的自主形态 = **预注册内的有界自主**：判据与门编码进驱动脚本，AI 在授权动作空间内
无人值守推进，越界即停。三个复核点（SKILL.md §6）不变。

## AI 可独走（须同时满足全部前提）

1. 对应预注册**已批准**，判据、门、各分支动作已写死；
2. 门在**代码里**：驱动脚本自己校验输入哈希、自己判门、只在 rc=0 后写 marker（fail-closed）；
3. 动作全部落在预注册授权范围内（探路 → 判门 → 按分支铺满 → 取回产物）；
4. 每达里程碑把产物**取回本地**；链路可断点续跑、重入安全（防双启）；
5. 常规排障**不改变协议口径、不重写判据、不换数据**（脚本加固、传输重试等属此类，须留痕登记）；
6. **实证锚定**：每个下一步动作都能写出"做 X 因为〈某文件〉显示 Y（值 Z）"——
   纯理论推理 / "感觉该试了"不构成行动授权（机制源自 gaasher/Agent-Loop-Skills 的 ml-autoresearch）。

## 必须停下（写入"待裁决"，不擅自行动）

| 情形 | 为什么停 |
|---|---|
| 输入哈希硬门未过 / 数据异常 | 可能是协议或数据问题，带病前进污染一切后续数字 |
| 门未过 | 门未过 = 预注册分支的 CLOSE/HOLD，**不是**"改门再试"的理由 |
| 出现预注册未覆盖的情形（新歧义、新资源需求、方案取舍） | 属于新决策，须新预注册或用户裁决 |
| 需要新 GPU / 磁盘 / 新数据集 / 外部服务 | 资源与授权边界 |
| 任何对外表述、汇报文稿定稿 | 复核点 3 |
| 因子关闭/重开、§10 修正案的执行 | 修正案起草可以，执行须用户批准 |
| 判据"看起来需要修改才能通过" | 这正是判据先行的用意：到点即停，不放宽 |
| 连续 N 次（建议 3）尝试无新 verified 结论 | **patience 停机**：如实汇报并停，不硬耗到时间上限 |
| 同一对象/复核点完成一次主审与一次整改复核，仍有阻断或争议 | 按 §6 复核上限登记待决，不自动第三轮，不因上限而通过；该上限独立于上一行探索 patience |

## 事前证伪（每个无人值守动作前）

- 动作启动前先写一句："**如果没用，我会看到什么**"；
- 结果与"没用的样子"相符 → 停、登记，不带解释地换法重跑；
- 与实证锚定句配合：锚定句管"为什么做"，事前证伪管"怎么算失败"。

## 阴性结果与运行失败登记

- 有效实验得到的阴性、无显著差异、未达预注册判据或证伪结果照实入账。与研究问题或所述结论相关且已核实的结果应在报告中如实呈现，不因不利于主张而排除；写明协议、估计值与不确定性，不把“不显著”当作已证明无效或等效。
- 运行失败、未完成和关键证据缺失单独登记状态、原因及可用产物，不能充当有效阴性结果；影响研究完整性、可重复性或结论时，在报告方法或局限中如实披露，不编造尚未得到的指标。
- 禁止把“没测出来”写成“基本达标”，或把噪声内变化写成“略有改善”。报告范围、正式定稿复核点3与发布授权仍按原规则；本节不新增重跑、实验或对外发布权限。

## 断言溯源标签（五分类）

对论文与结果的关键断言标注来源类别，**推断不许冒充已证实**（机制源自 zLanqing 证据标签法）：

| 标签 | 含义 |
|---|---|
| 论文原文 | 直接引自论文正文 |
| 图表公式证据 | 来自论文图表 / 公式 / 附录 |
| 代码仿真 | 来自我方或参考实现的代码运行结果 |
| 上下文推断 | 由上下文推测，**未经证实** |
| 建议 | 主观建议，非事实 |

- 缺失元数据时明确写"未在原文中明确给出"，不默认补全；
- 复核包与无人值守日志中的关键断言都应带标签。

## 灰区处理

无法明确归入上两栏的 → **默认按"必须停"处理**，把情形写成一段"待裁决"登记
（现象 / 已查事实 / 候选动作及各自代价），交给用户。宁可多停，不可越界。

## 与三复核点的衔接

- 自主推进**不取消**复核点：复核点 2 仍在正式判据出数后；
- autopilot 完成一轮后，下一轮预注册仍须走复核点 1；
- 无人值守链的日志与 marker 是复核点 2 的必查材料。
- 复核完成不等于通过；只有当前绑定有效且 `gate_passed=true` 才满足该复核门。通过仍不新增运行授权。
- 主会话负责授权内整改、实际验证与 README 登记；一般建议不阻断，执行阶段门不冒充当前阻断，也不豁免当前硬门。
- 实现阻断采用修复优先：复核方同次交patch/失败用例或精确受限原因，主会话检查版本与范围后落盘回归；不把来回转述当整改。
  门未过只停依赖步骤，普通修复须仍在授权内；暂停项目不能借整改重开，补丁不能改变科学设定或冻结证据。
- 两轮未通过标 `needs_user_decision`，否决标 `rejected_stop`；可交付明确的未通过结果，不追求必过、不自动第三轮。
  格式故障/输出截断是未完成，失败尝试留诊断但不消耗实质轮次，也不新增调用预算。写补丁不产生独立批准。

## 提示词自优化的边界（见 project-work.md §5 复盘步）

自主推进过程中 AI **不得**运行时自我修改本技能、项目 CLAUDE.md 或全局规则；
学到的约束一律走收尾复盘步（备份 → 登记 → 用户批准 → 版本号 +1）。
